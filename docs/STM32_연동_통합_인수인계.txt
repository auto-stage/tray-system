============================================================
0. 이 문서를 먼저 읽으면 되는 이유
============================================================

이 문서는 STM32 담당자가 현재 프로젝트 상황을 빠르게 파악하고,
자신의 STM32 파트를 Python Backend와 실제로 연결하기 위한 통합 인수인계 문서입니다.

기존에 따로 정리했던
- STM 담당자 현재 펌웨어 확인사항
- STM32 연동 인수인계 가이드

내용을 하나로 합쳤습니다.

이 파일 하나와 아래 핵심 코드 파일을 ChatGPT에 같이 올리면,
현재 구조를 설명한 뒤 STM32 연동 작업을 이어갈 수 있도록 작성했습니다.

3. 기존 STM32 펌웨어를 고려해서 Python 코드를 작성했는가?
============================================================

예.

Python의 STM32StageAdapter는 STM 담당자가 기존에 작성한 STM32 firmware의
UART 명령 구조를 최대한 그대로 사용하도록 작성했습니다.

현재 확인된 STM32 명령:

- PING
- STATUS
- ENABLE X 1
- ENABLE Z 1
- MOVE X <distance> <speed> <accel>
- MOVE Z <distance> <speed> <accel>
- HOME X
- HOME Z
- STOP ALL
- STOP ALL SOFT
- ESTOP
- RESET

즉 PC팀에서

MOVE:5
DONE:5

같은 새로운 프로토콜을 STM32에 강제로 추가하는 구조로 만들지 않았습니다.

기본 방향은:

기존 STM32 firmware 유지
→ Python STM32StageAdapter가 기존 명령에 맞춰 통신
→ 실제 장비에서 필요한 값과 예외만 조정

입니다.

현재 Tray 좌표는 실제 장비 측정 전이므로
실제 좌표값은 STM 담당자와 함께 측정해서 입력해야 합니다.


[필요하면 같이 확인]

backend/server.py

역할:

backend/workflow/workflow_controller.py

역할:
- 언제 Tray 이동을 요청하는지
- 이동 완료 후 다음 Workflow 단계로 어떻게 넘어가는지 확인


============================================================
5. 가장 중요한 부분: MOVE 완료 판단
============================================================

MOVE 명령을 STM32에 보낸 직후 OK 응답이 왔다고 해서
실제 모터 이동이 완료되었다고 판단하면 안 됩니다.

현재 Python에서 의도한 완료 판단 방식:

1) Python이 MOVE 명령 전송
2) STM32가 명령 접수 응답 반환
3) Python이 STATUS를 반복 확인
4) STATUS에서 mode가 IDLE인지 확인
5) 현재 X/Z 좌표가 목표 좌표에 도달했는지 확인
6) 두 조건이 만족되면 실제 이동 완료 처리

따라서 STM 담당자가 반드시 확인할 것:

- MOVE 직후 반환되는 OK가 단순 "명령 접수"인지
- 이동 중 STATUS의 mode 값이 무엇인지
- 이동 완료 시 mode가 확실하게 IDLE로 돌아오는지
- STATUS에 실제 X/Z 현재 좌표가 포함되는지
- 목표 좌표 도달 여부를 Python에서 판단할 수 있는지


============================================================
6. STM 담당자 실제 연결 추천 순서
============================================================

STEP 1. STM32 단독 테스트

Python과 연결하기 전에 현재 firmware 자체에서 아래를 먼저 검증:

- PING
- STATUS
- ENABLE
- HOME X
- HOME Z
- MOVE X
- MOVE Z
- X/Z 리밋 스위치
- STOP ALL
- STOP ALL SOFT
- ESTOP
- RESET

먼저 STM32 단독 상태에서 기구가 안전하게 동작하는지 확인합니다.


STEP 2. PC에서 COM Port 확인

STM32를 PC에 연결한 후 Windows 장치 관리자에서 COM Port 확인.

예:
COM3
COM5
COM7

baudrate도 현재 firmware 설정과 Python Adapter가 같은지 확인합니다.


STEP 3. Python과 통신만 먼저 확인

처음부터 모터를 움직이지 말고:

PING
→ STATUS

순서로 먼저 테스트합니다.

확인:
- 명령 송신 정상
- 응답 수신 정상
- 줄바꿈 형식
- 인코딩
- timeout
- STATUS JSON 파싱


STEP 4. HOME 테스트

Python Adapter를 통해 HOME을 실행.

확인:
- 실제 축이 올바른 방향으로 이동하는지
- 리밋을 정상 감지하는지
- homed 값이 정상적으로 바뀌는지
- HOME 완료 후 좌표 기준이 예상과 같은지


STEP 5. 작은 거리 MOVE 테스트

처음부터 Tray 위치로 크게 이동하지 않습니다.

충돌 위험이 없는 작은 값으로 X/Z 각각 테스트.

확인:
- 이동 방향
- 명령한 거리와 실제 거리
- speed
- accel
- 이동 중 STATUS mode
- 종료 후 IDLE
- 현재 좌표 정확성


STEP 6. Tray 1~6 실제 좌표 측정

실제 장비에서 각 Tray의 X/Z 위치를 측정하고:

backend/adapters/tray_positions.py

에 입력합니다.

중요:
좌표 기준점이 Python과 STM32에서 동일해야 합니다.


STEP 7. Mock → 실제 STM32 전환

단독 통신이 모두 정상일 때만 Backend의 StageAdapter를:

MockStageAdapter
→ STM32StageAdapter

로 교체합니다.


STEP 8. UI 전체 흐름 테스트

최종적으로:

UI
→ FastAPI Backend
→ WorkflowController
→ STM32StageAdapter
→ STM32
→ 실제 X/Z 이동

순서가 정상인지 확인합니다.


============================================================
7. 실제 장비에서 STM 담당자가 확인해야 할 항목
============================================================

1) HOME
- HOME X / HOME Z 정상 동작 여부
- homed=1 상태 확인
- HOME 후 좌표 기준

2) LIMIT
- X MIN / X MAX
- Z MIN / Z MAX
- 실제 입력 논리와 firmware 논리가 맞는지
- 리밋 감지 시 안전하게 정지하는지

3) MOVE
- MOVE 명령 형식
- OK 응답 의미
- 이동 중 추가 응답 여부

4) STATUS
- 실제 STATUS 예시
- 이동 중 mode
- 이동 완료 mode
- X/Z 현재 좌표
- homed 상태
- limit 상태
- error/fault 상태

5) Tray 위치
- Tray 1 X/Z
- Tray 2 X/Z
- Tray 3 X/Z
- Tray 4 X/Z
- Tray 5 X/Z
- Tray 6 X/Z

6) 이동 안전성
- X → Z 순서로 이동해도 안전한지
- Z → X가 필요한 구간이 있는지
- Tray 또는 기구 간섭 가능성

7) 속도 / 가속도
- 권장 speed
- 권장 accel
- 적재 상태에서도 안전한 값

8) PAUSE / RESUME
- 현재 별도 PAUSE / RESUME 명령이 없는 상태
- STOP ALL SOFT 후 같은 목표 위치를 재명령하는 방식이 가능한지
- 아니라면 STM 측 권장 방식

9) E-STOP
- 최종 장비에서 물리 E-STOP 입력 활성화 여부
- E-STOP 시 STM 내부 상태
- PC에 전달 가능한 상태
- E-STOP 해제 후 복구 절차

10) ERROR / FAULT
- 오류 발생 시 어떤 상태를 반환하는지
- RESET이 필요한지
- HOME이 필요한지
- 자동 HOME이 위험한 경우가 있는지

13. 한 줄 요약
============================================================

현재 STM32 연동 작업은

"STM32 firmware를 새로 만드는 작업"이 아니라

"이미 존재하는 STM firmware의 HOME / MOVE / STATUS 등의 명령을
Python STM32StageAdapter와 실제 하드웨어 기준으로 맞추고,
Tray 실제 좌표를 입력한 뒤 MockStageAdapter를 실제 Adapter로 교체하는 작업"

입니다.
